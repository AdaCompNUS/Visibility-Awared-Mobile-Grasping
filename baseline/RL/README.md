# RL Baseline — MS-HAB SAC (unmodified)

Image-input RL baseline: the SAC Pick policy from **ManiSkill-HAB** (ICLR
2025), trained with the upstream code, configs, environments, and assets —
nothing modified. SG-VLA trains on data generated by these same policies, so
this one training run anchors both learning baselines.

## Provenance (pinned in root `pixi.toml` and `pixi.lock`)

| Component | Source | Commit |
| --------- | ------ | ------ |
| ManiSkill3 | `haosulab/ManiSkill` @ branch `mshab` | `17121e3f96e3` |
| MS-HAB | `arth-shukla/mshab` @ `main` | `e9ff3d23496d` |

`configs/` and `scripts/` are verbatim copies from the mshab repo at that
commit, kept for reference; the installed `mshab` package is the import source.

## Layout (untracked, see `.gitignore`)

- `assets/` — `MS_ASSET_DIR` for this baseline only. Separate tree because
  MS-HAB's ReplicaCAD download **deletes** the target scene-dataset directory;
  it must never point at the main project's assets.
- `mshab_checkpoints/` — released checkpoints/configs from HuggingFace
  (`arth-shukla/mshab_checkpoints`), used for the exact training
  hyperparameters and as reference policies.
- `mshab_exps/` — training runs (checkpoints, logs).

## Usage

```bash
pixi run -e rl rl-smoke              # env sanity check
pixi run -e rl rl-download-assets    # ycb + ReplicaCAD + ReplicaCADRearrange
pixi run -e rl rl-train              # SEED=0 GPU=1 by default; see train.sh
SEED=1 GPU=2 pixi run -e rl rl-train # second seed on the other GPU
```

Training setup = upstream `scripts/train_sac.sh` defaults: task `tidy_house`,
subtask `pick`, split `train`, objects `all`, i.e. one SAC policy over all YCB
objects. When the released checkpoint config
(`mshab_checkpoints/rl/tidy_house/pick/all/config.yml`) is present, `train.sh`
trains with those exact hyperparameters (the authors note the shell-script
defaults may differ from what the checkpoints used); otherwise it falls back to
the upstream script's arguments. Budget follows the paper: 50M steps for Pick.

## Evaluation on our benchmark (next phase, not built yet)

The trained policy is exported as plain torch weights and evaluated inside the
*main* project environment against `resources/grasp_benchmark.json` (same
success rule as all other baselines: 2s stable hold, zero non-gripper
collision). Notes for that phase:

- benchmark env must run `control_mode="pd_joint_delta_pos"` for this policy
  (the main pipeline uses `pd_joint_vel`; both are stock Fetch controllers);
- observation adapter: 2x 128x128 head+hand RGBD, 3-frame stack, plus the
  privileged state vector (target pose, goal, TCP pose) the policy was trained
  with — supplied from sim ground truth, which favors the baseline and should
  be reported as such;
- the policy was trained spawning <=2m from the target with navigation
  teleported and the head stationary; our benchmark requires real navigation.
  Report both end-to-end and oracle-nav (base driven to a pre-pose by our
  planner) numbers.
